# 09 · 接入与集成

> 两条「从外面接进来」的路：**QQ**（人来 → 猫）与 **HTTP 通道**（程序来 → 猫 / 群）。
> 两者都不改变宿主的运行方式——只是给猫多开几个能收到消息、能发消息的口子。

## 一、总览

| 面 | 谁在用 | 入口 | 出口 | 认证 |
|:--|:--|:--|:--|:--|
| **浏览器** | 人 | 本机面板 / 对话页 | 面板内展示 | console 口令（主端口） |
| **QQ** | 人 | @ 机器人（群 / 私聊） | 主动发言 · 命令回复 | 机器人凭据（配置池） |
| **HTTP 通道** | **外部程序** | `POST /api/v1/channels/inject` | `POST /api/v1/channels/publish` | 通道 Key |

三者的**运行容器是同一批猫**——同一只猫可以在浏览器里对话、在 QQ 群里被 @、被外部程序唤醒。

## 二、QQ 通道

### 怎么工作

**2 入 1 出：**

| 方向 | 行为 |
|:--|:--|
| **@ 入口** | 群里 @ 到机器人（或私聊）→ 消息推给**绑定的那只猫**，按普通用户消息处理 |
| **全量留档** | 未被 @ 的群消息不打扰猫，但**按群按日留档**（`Data/qq/`）——需要时可回查 |
| **主动出口** | 猫用 `qqbot-send` 主动往群里发消息（无 msg_id，走平台主动发言额度） |

### 命令（仅在 @ 且以 `/` 开头时）

| 命令 | 作用 |
|:--|:--|
| `/ping` | 通不通 |
| `/help` | 命令清单 |
| `/botinfo` | 机器人所在群与权限（官方体优先，不可用时明示「未确认」） |
| `/homeinfo` | 宿主自述——版本 / 时间 / 系统 / 在线机器人 |

### 绑定与白名单（每猫四字段）

| 字段 | 含义 |
|:--|:--|
| `qqbotId` | 绑定的机器人（空 = 未绑定） |
| `qqbotEnable` | 是否收信 |
| `qqbotGroups` | 渠道白名单（别名 / 群名 / OpenID；**空 = 目录内全部群**） |
| `qqbotCanSend` | 是否允许主动发言 |

> 一个机器人对应一只猫。群目录（群名 / 别名 / 权限 / 主动发言开关）在面板里维护，`qqbot-groups` 工具可查可改。

### 频控（平台侧，非本系统设定）

主动发言：20 条/分钟/群、1000 条/群/天；命令回复另有更严的限制。超限由平台拒绝，错误原文透传给调用方。

## 三、HTTP 通道（外部程序接入）

### 它是什么

**通道 = 「一把 Key → 一组能力」的实体。** 外部程序**只持 Key**，永远不知道猫的标识——服务端按 Key 反查，调用方无法越权指定目标。

一个通道可以配两种能力（至少配一项）：

| 能力 | 字段 | 行为 |
|:--|:--|:--|
| **注入** | 绑定猫 | 往该猫的会话里投一条系统消息（唤醒 / 忙时排队），语义与定时唤醒同源 |
| **播报** | 出口机器人 + 群白名单 | 往白名单里的群各发一条消息（对外可见） |

### 怎么建

面板「配置页 → HTTP 注入通道」区块：填通道名 → 选绑定猫（可留空 = 仅播报）→ 填出口机器人与允许群（可留空 = 仅注入）→ 保存。

🔴 **Key 明文只在新建 / 重置时显示一次**——弹层里复制走，之后只显示掩码；忘了只能重置（旧 Key 当场作废）。

### 注入（唤醒某只猫）

```
POST /api/v1/channels/inject
Authorization: Bearer <通道Key>          （或 X-Channel-Key: <通道Key>）
{"text": "轮到你发言了"}
```

| 状态码 | 含义 |
|:--:|:--|
| 200 | 已受理（进队列；**不等于已被模型处理**） |
| 400 | 请求体非法 / 正文为空或超长（上限 32768 字符） |
| 401 | 无 Key / Key 无效 |
| 403 | 该通道未配注入目标（纯播报通道） |
| 409 | 绑定猫未运行（**不自动拉起**，由外部程序决定） |
| 503 | 宿主重启停机态 |

### 播报（往群里发）

```
POST /api/v1/channels/publish
Authorization: Bearer <通道Key>
{"text": "第 1 夜结束，天亮了"}
```

🔴 **广播语义：通道白名单即目标集**——一次调用向白名单内**每个群各发一份**，填两个群就是发两遍；白名单空 = 禁发。请求体只带 `text`，**不接受群参数**——想只发某一个群，就建只含该群的通道。

| 状态码 | 含义 |
|:--:|:--|
| 200 | 全部群成功 |
| 207 | 部分成功（逐群明细在回执里，成功的不回滚） |
| 400 | 请求体非法 / 出现未知参数 |
| 401 | 无 Key / Key 无效 |
| 403 | 未配出口机器人 / 白名单为空 / 机器人未连接 |
| 404 | 白名单里的群在目录中找不到（附候选） |
| 502 | 平台侧拒绝（超频 / 无权限 / 未开主动发言）——原文透传 |
| 503 | 宿主重启停机态 |

### 两条边界

- **与口令闸的关系**：通道端点对 console 口令**精确豁免**，Key 校验在端点内部——人面口令换不到注入权，通道 Key 也打不开管理端点。
- **不经过猫级闸**：播报的调用方是通道不是猫，所以不受猫的 `qqbotCanSend` 等字段约束——要限制某外部程序能发哪些群，用**通道自己的群白名单**。

## 四、我该用哪条

| 我想做的事 | 用什么 |
|:--|:--|
| 在群里跟猫说话 | QQ：@ 机器人 |
| 让猫定时/不定期往群里发消息 | 猫用 `qqbot-send`（会话内主动出口） |
| 外部程序（脚本 / 另一套系统）事件驱动地唤醒某只猫 | HTTP 通道 · `inject` |
| 外部程序往若干群广播一条通知 | HTTP 通道 · `publish`（白名单即目标集） |
| 让别的猫干一件事（都在本宿主内） | 工具面 `group-delegate`（群组机制，见 05） |

> QQ 配置池与凭据的存放 → 07 数据目录（`config/` + `secrets/`）。
