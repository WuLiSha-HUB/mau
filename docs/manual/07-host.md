# 07 · 宿主与部署

> 宿主 = CatHome4 进程。本章讲它怎么跑、数据在哪、怎么观测、怎么部署与重启。

## 运行形态

- **GUI 外壳**（Windows）——不启前台控制台窗口。三层线程：runtime（Main·进程生命线）/ 任务栏 UI（托盘常驻）/ GUI（总控窗·按需起停）。
- **托盘常驻**：左键开控制台；右键菜单——开机自启 / 打开数据目录 / 显示控制台 / 退出。关掉总控窗 ≠ 退出（托盘图标仍在）。
- **服务形态**（Linux）——无头运行，由 systemd 托管（`Restart=always`），无托盘。
- **端口**：管理面板（部署区 `8080` / 开发区 `8079`）；每猫对话页独立端口；群聊宿主每组一个端口（`9000–9099`）。
- **端口分区**：开发区（8079 向下）/ 部署区（8080 向上）——两区可同时运行。端口单例——同区占用即报错。

## 口令与访问控制

主端口（console 管理面）可设**访问口令**：

- **设置**：首次打开面板时提示设置（至少 6 位）——口令只以不可逆哈希落盘（PBKDF2-SHA256），存 `auth.console_hash`。
- **登录**：口令设置后，主端口全部 `/api/v1/*` 请求须带令牌；令牌**只存浏览器内存**——刷新页面即需重输。
- **会话端口不设口令**：每猫对话端口、组端口不做校验（本机回环，允许的范围与工具面等价）。
- **断联语义**：SSE 断联即视为未认证——遮罩切「断联态」（无输入框），后台每 10 秒探测，恢复后重输口令。
- **忘了口令**：删除配置项 `auth.console_hash`（或对应配置键）即回到「无口令」模式，之后可重新设置。

> 这条是**认证**不是加密——防的是同机进程误触管理面，不防同用户下的内存读取；回环流量不出机器。

## 数据目录

正式实例持久区（Windows）：`%LOCALAPPDATA%\CatHome4\Data`；Linux：`CH4_DATA_ROOT` 指向的目录（如 `/cathome4/data/Data`）。

| 子目录 | 内容 |
|:--|:--|
| `config/` | 配置群——全局 / 每猫默认 / 界面 / 搜索 / 视觉 / 浏览器 / 受控根表 / 通道池 |
| `secrets/` | 密钥——LLM 端点与密钥、QQ 凭据、通道 Key（**不进对话、不进快照**） |
| `sessions/` | 每猫一个目录——会话前文、视图层、该猫配置、会话元数据 |
| `sessions_old/` | 会话留档（新会话时旧会话的沉淀档案） |
| `runs/` | 每次运行一个目录——日志、工单轨迹、错误、状态快照 |
| `qq/` | QQ 通道留档（按群按日 JSONL）与收发文件缓存 |
| `tokennumber/` | Token 用量流水（每猫一目录，按日一行一请求） |
| `tts/` | 语音合成产物 |
| `db/` | 条目库（Smriti）数据 |

**数据位置三级：** `CH4_DATA_ROOT` 环境变量 → 仓库根 `Data/`（就地开发隔离区）→ `%LOCALAPPDATA%\CatHome4\Data`（正式持久区）。正式实例的数据恒在第三级——仓库怎么折腾都不丢。

## 观测（出问题回看每一步）

| 文件（`runs/<时间戳>/`） | 内容 |
|:--|:--|
| `log_all.txt` | 全量时序（主文件） |
| `oa_all.txt` | 工单时序——审计帧号（post→claim→complete→unregister 断在哪一帧） |
| `err_all.txt` | 只收错误（**排查第一入口**） |
| `frame.txt` | 连续快照（250ms 一行） |

- 分级：INFO / WARN / ERR。trace 类只留内存（可查、不落盘）。
- HTTP 查询：`GET /api/v1/logs?n=&type=`。
- **帧号差 = 执行耗时**：`T_*Exec` 帧 − `T_*Args` 帧 ≈ 耗时 / 50ms——帧差大 = 主循环在推进，帧差 1-2 = 同步阻塞。
- **用量**：面板「用量」页签——按猫按日聚合 Token 消耗（后台每分钟重算，可手动刷新）；明细源 = `tokennumber/` 流水。

## CLI 通道（脚本化）

| 参数 | 用途 |
|:--|:--|
| 无参 | 常驻交互 |
| `--run "指令"` | 单指令脚本模式（主线程直执 + 进程自退） |
| `--script <file>` | 指令文件批量模式 |
| `--selfcheck` | 启动自检 |
| `--probe-llm <目标>` | LLM 返回体探针 |

**非交互输出双写落盘**（WinExe 无控制台 stdout）——`runs/cmd_<时间戳>.txt`，落点是**该实例自己的数据根**。

## 部署（SetUp）

`SetUp.exe`（Windows）/ `SetUp-linux`（Linux ELF）放在**仓库根**，与 `Mau.sln` 同级。命令行模式（**无 GUI**，无参打印帮助）：

```
SetUp.exe prepare                  ← 仓库内重建（宿主照常运行）· 唯一版本自增点
SetUp.exe deploy C:\MauTest\MauOut ← 发布正式运行实体到仓库外（原子切换）
SetUp.exe sync-html                ← 前端静态资源镜像同步（源区 → 产物区 + 运行区）
SetUp.exe publish-linux            ← Linux 交叉发布产物（public/app-linux）· 不自增版本
```

🔴 **必须部署到仓库之外**——部署目录是正式运行实体，与仓库解耦。

**前端资源轻量通道：** 改 `html/**` 后 `SetUp sync-html`（或工具面 `mau-setup mode=sync-html`）——刷新即生效，不走全链、不重启。

## 更新与重启

改完源码后：

1. **仓库内 prepare**——重编 + 刷新产物（宿主照常运行，不全频阻塞）。
2. **重启**——经特权链（仅管理面可发起）：

| 档 | 判据 | 版本 | 阻塞 |
|:--|:--|:--|:--|
| `restart-full` | 版本自增发布 / 全链保底 / 仓库内 prepare 不可行 | 自增 | ~70s |
| `restart-incr` | **默认**——产物已 prepare 就绪 | 不变 | ~10s |
| `restart-host` | 无编译无覆盖——仅重启进程（配置面变更 / 异常恢复） | 不变 | ~10s |

**默认：** 仓库内 `prepare` + `restart-incr`。重启前置零停机；**验证不过则保持在原版本运行**（天然回退）。

**托管环境（Linux / systemd）：** `full` 被拒；`incr` 完成切换后退出、由 systemd 拉起；`host` 原地退出再拉起。回执落 `restart_push.txt`。

## Linux 部署（简报）

> 完整流程与每步判据见 `tools/deploy/` 与部署链文档；这里是三条硬约束与一次常规迭代的主干。

**核心模型：构建在开发机，运行机只接收产物。**

| # | 约束 | 理由 |
|:--:|:--|:--|
| 1 | **接收端零编译** | 云端小机跑全链极慢；编译产物不一致时排查成本极高 |
| 2 | **包必须自足** | 宿主产物 + Flows + 前端全部在包内——只推宿主会让 Flow 与宿主版本错配，全部工具组挂掉 |
| 3 | **三处同版本** | 仓库版本单点 = 本地 CLI = 本地 publish 产物 |

一次常规迭代：

```
[开发机]  git pull → SetUp prepare（刷新 Windows 产物 + 版本自增）
          → tools/deploy/push-app.ps1（publish-linux + 打包 + scp）→ /srv/inbox   ← 开发机到此为止
[远端]    git pull → take-app.sh（结构闸 + 指纹闸 → 覆盖产物区）→ restart-incr → 核验三件
```

**四个位置别搞混：** 投放区（`/srv/inbox`，待取包）· 产物区（`public/app`，`take-app` 覆盖）· 运行区（实际执行目录，`restart-incr` 原子切换）· 数据区（`CH4_DATA_ROOT`，**部署不触碰**）。

**核验三件：** `cat <运行区>/version.txt` · `systemctl is-active cathome4` · `curl -s 127.0.0.1:8080/api/v1/auth/status`。

🔴 **分工边界：** 开发机只到「包落 `/srv/inbox`」，其后的取包 / 切换 / 重启 / 核验归远端自己。

## 配置写入通道

`Data` 受控根只读——写配置经面板（`POST /api/v1/config`、`/api/v1/cat-config`）或工具面（`config-set` / `config-cat-set`）。配置面为纯键值：合法键直接可写，读面只输出已落盘键值；**清空某项 = 删除该项落盘值**。
